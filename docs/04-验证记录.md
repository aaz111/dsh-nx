## 用例 C：有限元与解析解的独立对照

|---|---|---|---|---|

## 自查方法

- 任何特征之后都用 `nx_measure` 对照解析体积：块 `L·W·H`，圆柱 `πr²h`，凸台融合 `V1+V2−重叠`，
  孔 `−πr²·深`，倒角 `4·(r²−πr²/4)·厚度`。
- 导出后用 `Select-String` 数 STEP 里的 `MANIFOLD_SOLID_BREP` / `ADVANCED_FACE`，与 `nx_measure` 的面数对照。
- 有限元用 `δ=FL³/3EI` 与 `σ=6FL/(bh²)` 校验，偏差 >5% 就查网格密度或载荷施加面。

## 用例 J：预览渲染回归（0.3.0）

- 剖切碎片：`clipPolygon` 产出的 4–5 顶点只画了前 3 个 → 改扇形三角化。
- 背面剔除：绕向不一致的网格会丢可见面 → 去掉剔除，靠 z-buffer。
- 螺纹黑糊：`max(0, dot)` 单面光照 + crease 阈值 0.965 → 改双面 `abs(dot)` + 阈值 0.5。
- 上下颠倒：Z-up→Y-up 映射把 +Z 落到 viewer −Y → 改为 `(z, -y)`。
- ASCII STL 丢面：正则字符类缺 `-`，`8.57e-01` 被截断 → 补 `-`。
- 片体只显示一片：预览导出没传 `bodies` → 传 `"all"`，缓存升 `v4-`；信息卡按水密性区分实体/片体。

## 用例 S：局部剖（breakout）尝试（0.5.1，未通过）

目标：补上 A2 装配图 issue 里第五件（局部剖）。结论：Python 批处理侧不可实现，证据如下。

| 步骤 | 调用 | 实际结果 |
| --- | --- | --- |
| 定位接口 | `uf.Draw.CreateBreakout` / `SetBreakoutData` / `AskBreakoutData` / `RemoveBreakout` | 均存在，文档签名 `CreateBreakout(viewTag, breakoutData)` |

| 提交 | `uf.Draw.CreateBreakout(39622, data)`（39622 = Front@1） | `TypeError: Second parameter is invalid. Expecting NXOpen.UF.Draw.BreakoutData type.` |
| 排除误用 | `isinstance(data, uf.Draw.BreakoutData)`、`type(data) is uf.Draw.BreakoutData` | 都为 `True`；`uf.Draw.BreakoutData is NXOpen.UF.DrawBreakoutData_Struct` 也为 `True` |
| 判定 | —— | 绑定按 `NXOpen.UF.Draw.BreakoutData` 路径找类型，而 `uf.Draw` 是类不是模块，该路径不存在 → 任何对象都匹配不上，属 NX 绑定缺陷（同一批 `CreateSimpleSxview` 吃 `DrfObject_Struct` 正常） |

- `uf.Draw.CreateBreakRegion(viewTag, anchorPoint, numCurves, curves)` 与 `NXOpen.Drawings.ViewBreakBuilder` / `ViewBreakCollection` 是**打断视图**（长件中间删一段），不是局部剖。

替代方案（未做成工具）：

1. GUI 手动：视图框内画闭合边界 → 局部剖命令 → 定深度与方向。步骤短，人工更快。
