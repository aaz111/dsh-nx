# 架构与原理

## 为什么不是"每次调用启一个 NX"

`run_journal.exe <script>` 是唯一能在无界面下跑 NXOpen 的入口，但它有两条硬约束：

1. **冷启动约 25 s**（加载 NX + 许可 + 模块）；
2. **journal 跑完 NX 就退出**，不保留 part 与内存状态。

所以"一条命令 = 一次 NX 启动"完全不可用。插件改成：**启动一次常驻 worker，之后用文件队列发命令**。
第一次 `nx_*` 调用付出 25 s 冷启动，此后单条命令往返 **0.1–0.6 s**（导出/打印/求解除外）。

## 进程与数据流

```
DSH 主进程
  └─ lib/index.js          注册 30 个工具 + 注入系统提示词
       └─ lib/bridge.js    NxBridge（Node）
            │  spawn(detached, unref)  run_journal.exe python/nxworker.py
            ▼
        NX 进程（常驻，会话里只有一个 part 上下文）
            │  轮询  <root>\req\*.json       ← 请求：{"id","cmd","args"}
            ▼
        写回    <root>\resp\<id>.json        → 响应：{"id","ok","result"|"error","trace","log","ms"}
```

`<root>` 默认 `%USERPROFILE%\.dsh-nx\bridge`，可被插件配置 `root` 覆盖。目录里有：

| 文件 | 作用 |
|---|---|
| `ready.json` | worker 就绪标志，含 `pid` 与 `commands`（暴露给 `nx_status`） |
| `req\` / `resp\` | 请求/响应用的一次性文件（原子写：先写 `.tmp` 再 `os.replace`） |
| `bridge.log` | worker 侧日志（每条命令的 cmd、耗时、异常） |
| `fatal.log` | 未捕获异常（worker 崩溃原因在这里） |

### 关键设计决定

- **detached + unref**：NX 会话持有已打开的 part，必须比调用方活得久。若不 detach，Node 退出就把 NX 杀掉，下一次又要 25 s。
- **请求串行化**：NXOpen 不是线程安全的，`NxBridge` 内部用 promise 链排成队列，一条一条发。
- **超时即杀**：单条命令超时（如 DXF 翻译器挂死）后 `taskkill /pid <pid> /T /F`，抛 `NX command "…" timed out after Ns; the NX session was stopped`。下一次调用重新拉起会话。
- **中文文件名**：NX 返回的字符串是 GBK 字节按 UTF-8 解出来的乱码，worker 里所有回传字符串都过 `fix_text()`（`s.encode("gbk").decode("utf-8")`，失败则原样返回）。
- **写文件编码**：读请求容忍 BOM（`utf-8-sig`），写响应一律 UTF-8 无 BOM；PowerShell 侧必须用 `[IO.File]::WriteAllText(path, text, UTF8Encoding($false))`，`Out-File -Encoding ascii` 会毁掉中文路径。

## 工具层为什么长这样

`defineTool` 的 `output` **必须**是合法的 value schema。本项目实测：只写 `output: { render }`、或
`{type:'object', properties:{}, additionalProperties:true}` 都会被 DSH 拒绝（`JsonSchemaError: unsupported JSON schema`）。
采用官方写法：

```js
output: {
  schema: { type: 'string' },
  render: (_args, value) => [{ type: 'text', text: value }],
}
```

所以每个工具的 `execute` 最终返回**一段已经排版好的文本**（内部先把结构化结果排成若干行再 `join('\n')`）。
同样，参数里凡是 `type:'object'` 的（`views`、配合的 `a`/`b`、`material`、`spec`）都必须显式写
`additionalProperties: false`，否则整包加载失败。

参数层还有一个限制：**嵌套数组会被当成字符串传下来**（`edges: [[x,y,z],…]` → `invalid arguments: "edges" must be an array`）。
因此点/轮廓参数统一改成**扁平数字数组**，在 JS 侧用 `group(values, size)` 分组：

```js
function group(values, size, what) {
  if (!Array.isArray(values)) return [];
  if (Array.isArray(values[0])) return values;          // 兼容已是嵌套
  if (typeof values === 'string') { /* "x,y,z; x,y,z" 解析 */ }
  if (values.length % size) throw new Error(`${what} needs a multiple of ${size} numbers, got ${values.length}`);
  /* 按 size 切块 */
}
```

## 加一个新能力（三步）

1. **worker**：在 `nxworker.py` 里写 `def cmd_xxx(args): …`，并注册进 `handlers = {… "xxx": cmd_xxx}`。
2. **工具**：在 `lib/tools.js` 里 `tools.push(make({ name: 'nx_xxx', description, parameters, timeoutMs, run: (a) => call('xxx', a, ms), render }))`。
3. **提示词**（可选）：在 `lib/prompt.js` 的 GUIDE 里加一行，让模型知道什么时候用它。

更新方式：改 JS → `plugin_manager set_bundle enabled=false` 再 `=true`；改 Python → `nx_session action=restart`。

## 调试

- `nx_status` 先看会话在不在；不在就调一次任意建模工具触发冷启动。
- 命令报错时错误里带有 Python traceback（worker 把 `traceback.format_exc()` 一起回传）。
- 想看 NX 内部状态：`nx_python` 里直接 `w(str([n for n in dir(part) if 'Draft' in n]))`。
- worker 崩溃：看 `<root>\fatal.log`；起不来先 `python -m py_compile python/nxworker.py`（语法错误会让会话启动静默超时）。
- 想脱开 DSH 单独压测：用一个 node 脚本直接 `new NxBridge({root})` + `createNxTools(bridge)`，逐个调 `tool.execute(args)`。

## 面板路由（0.2.0）

`lib/index.js` 在 `config.panel !== false` 时执行 `ctx.inject(['webServer'], ...)`，调用
`registerPanelRoutes({ webServer, bridge, outputDir })`：

- `webServer.register({ kind: 'exact', path: '/dsh-nx/state', handler })` 与
  `{ kind: 'exact', path: '/dsh-nx/action', handler }`，每个 register 返回 disposer，
  统一在 `panelCtx.effect(() => () => dispose())` 里释放。
- `state` 只用 `bridge.status()` 读 ready.json（毫秒级，不唤醒 NX）；`?probe=1` 才发
  `bridge.request('status')`，超时 30 s 并把错误放进 `probeError` 而不是抛 500。
- `action` 先查 `PANEL_COMMANDS` 白名单（不在内 → HTTP 400），再用 `withDefaults()` 补
  输出路径（`export`/`pdf`/`asm_bom`），最后 `bridge.request(command, args, { timeoutMs })`。
- 请求体上限 64 KB；响应统一 `application/json` + `cache-control: no-store`。

客户端 `client.js` 是浏览器端模块（`window.__ModuleLoader__.load({ id: 'dsh-nx', factory })`），
用 `require('react')` 取宿主 React，注册两个 slot：

```js
ctx.slots.inject('sidebar.panellist', () => ctx.slots.register(
  { name: 'sidebar.panellist', id: 'dsh-nx', order: 2, label: () => 'NX' }, NxIcon))
ctx.slots.inject('main', () => ctx.slots.register({ name: 'main', key: 'dsh-nx' }, NxPanel))
```

`NxPanel` 每 5 秒 `fetch(api('/dsh-nx/state'))`，组件卸载时清定时器。

## 0.3.0 新增的纯 python 模块

FE 与表格这两块都在 NX 会话之外算：

| 文件 | 职责 |
| --- | --- |
| `python/cae_solid.py` | STL → 体素 CHEXA8 网格 → BDF（SOL 101 / SOL 103）→ 起 Nastran → 解析 `.f06`。载荷 force/pressure/moment/gravity/centrifugal 全部转成节点力，因为 Nastran 不允许同一载荷集混用 GRAV 与 FORCE |
| `python/cae_drape.py` | 把体素网格的外表面节点投影到 STL 真实曲面（半径 0.85h），一轮拉普拉斯松弛后重新投影；任何会翻转单元的移动都回退 |
| `python/cae_plot.py` | numpy 光栅器 + Pillow 标注出位移 / von Mises 云图（本机没有 matplotlib）；正交相机、重心插值、z-buffer、五色阶 + 独立色标 |
| `python/cae_run.py` | 0.1.x 的盒子梁链路，保留给 `nx_fea_solve` |

`nx_fea_solid` 的 spec 里带 `"mesh": "draped" | "voxel"`，以及 `source.volume`（CAD 实测体积）
用来在结果里报告体积误差。载荷/约束的选面**一律在铺面之前的名义盒子上做**
（`reference_nodes()`），否则被拖动的边界节点跑出容差带，固定节点数、受压面积、力臂都会漂。

明细表与批量出图没有走 NX 的表格 API（它没有）：`cmd_bom_table` 在图纸上 `part.Curves.CreateLine`
画框线（图纸坐标，毫米），每格一个 `DraftingNote`，`Delta` 用 `chinesef` 字体。数字来自
`bom_rollup()`，与 `nx_assembly_bom` 同一份汇总，所以图纸和 JSON 不会打架。
`cmd_batch_drawings` 逐件 `open → drawing（若无图纸）→ sheet_info → pdf`，单件异常只记录不中断。
