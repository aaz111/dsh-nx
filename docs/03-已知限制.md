# 已知限制（batch 会话下 NX 做不到的事）

下面每一条都是在本机 NX 2512.3002 + `run_journal.exe` 无界面会话里**实测**出来的，带现象与证据。
设计流程时绕开它们，别反复尝试。

## 1. DXF / DWG 导出必挂死

`DexManager.CreateDxfdwgCreator()` 能建对象，设好 `ExportFrom=DisplayPart`、`ExportData=Drawing|Modeling`、
`DrawingList`、`OutputFileType=Dxf` 后，`Commit()` **永不返回**（>100 s 无响应），只能杀进程重启会话。

- 证据：`ExportData=Modeling` 与 `=Drawing` 两次都卡在 `before commit`；`UGTO2D`/`DXFDWG` 目录存在但翻译器不工作。
- 绕法：不提供该能力。需要 2D 交换格式时，用 `nx_pdf` 出图，或用 `nx_python` 从视图曲线自己生成 DXF。

## 2. 无法创建原生尺寸标注

`part.Annotations.CreateAssociateDimensionBuilder(x)` **必须传一个已存在的尺寸对象**：
不传报 `Function takes 1 arguments, 0 passed.`，传 `None` 或 `NX.Annotations.Dimension.Null` 报
`The input object is a null entity.` —— 它只能"编辑/关联"已有尺寸，不能新建。

- `nx_annotate` 走的是 `Drafting.AutomationManager.CreateAnnotateViewsBuilder()`，只从 NX PMI 自动标注；
  普通导入实体或自己建的实体没有 PMI，**结果就是没有尺寸**。
- 绕法：尺寸写在交付说明里，或用 `nx_python` 建注释文字（`CreateDraftingNoteBuilder`）。

## 3. 从模板建的图幅，打印时没有图框与标题栏

`part.DrawingSheets.SheetTemplates.Create("D:\software\NX\DRAFTING\templates\Drawing-A3-Size-template.prt")`
能建出 420×297 的正确图幅，视图也正常，但 `nx_pdf` 打出来的 PDF **只有视图线条**。

- 本机证据：装配图 PDF 4683 B，内容流 12274 B 只有 `118 m / 535 l / 12 c / 8 S`，**没有 `Tj`（文字）、没有填充指令**；
  `part.Drafting.BordersAndZonesObjects` 长度 = 0。
- 对照：会话早期**偶发成功过一次**（`tmpl_sheet.pdf` 67478 B，内容流 170 KB，262 个填充、45 段文字），
  说明能力存在但当前批处理会话里无法稳定复现。
- 已试过并失败：`CustomSymbolsInForeground=True` + `OutputText=Polylines`；换 `Drawing-A3-Size2D-template.prt`；
  先 `EnterDraftingApplication()` 再建模板图幅；找 `Layout-A3-Size2D-template.prt`（该文件不存在）。
- 绕法：向用户如实说明"图幅+四视图，但无模板图框"；要图框就在 `nx_python` 里于图纸草图（`sheet.ActivateForSketching()`）自绘国标图框。

## 4. 视图不能手工移动

`view.SetOrigin(pt)` 抛 `View may not be scaled nor translated`；`view.MoveView(pt)` 返回成功但 `view.Origin`
不变（恒为 `(0.371, -0.294)`）。

- 绕法：只用 `nx_drawing`（`CreateViewCreationWizardBuilder` + `wiz.Part = part` 后 `Commit()`），它自动摆位并自动定比例。

## 5. 装配求解器只登记约束，不移动几何

建约束（concentric/touch/distance…）后 `status` 为 0，自由度也会下降（例如 touch 让 3,3 → 2,1），但
`Network.Solve()` + `UpdateManager.DoAssemblyConstraintsUpdate(1)` / `DoUpdate(1)` **都不会改变组件位置**。

- 例外：`Fix` 真生效（自由度 3,3 → 0,0）。
- 绕法：用 `nx_assembly_move` 精确摆放，用 `nx_assembly_gap` 验证（0 = 贴合），配合约束只作为文档/后续交互求解的基础。

## 6. 装配体 STEP 导出必须读磁盘文件

- 装配 part 的 `part.Bodies` 为空（几何在组件里），直接用 `DisplayPart` 导出报 `No parts in current input file`、不产文件。
- 正确做法（`nx_export` 已内置）：`ExportFrom=ExistingPart` + `InputFile=<已保存的 .prt>`。
  **所以装配体必须先 `nx_save`**。
- 深层嵌套装配可能导不出东西：实测课设.prt（27 个子件，紧固件 Prototype 是 `NXObject` 没有 `Bodies`）→
  `step export produced no file (bodies offered: 0, accepted: 0)`。

## 7. STEP 导出需要非空层掩码

`StepCreator.LayerMask` 默认是**空字符串**，此时翻译器"成功"返回但产物里 **0 个实体**（日志
`Total number of solids input : 0`）。必须同时满足：`LayerMask="1-256"`、`ObjectTypes.Solids=True`、
`ExportFrom` 与选择集正确 —— 三个开关缺一不可。`nx_export` 已全部设好。

翻译器是**异步**的：`Commit()` 立刻返回，文件与同名 `.log` 约 20 s 后才出现，工具会轮询等待。

## 8. 曲面/壳体相关

| 操作 | 现象 | 绕法 |
|---|---|---|
| `nx_shell` 不给 tolerance | `NXException('Tolerance error.')` | 必须传 `tolerance`，默认 0.01；0.001 反而报 `Unable to perform Boolean.` |
| `nx_fillet` 半径过大/边太多 | `NXException: Blend faces overlap. Try blending the edges in separate features.` | 分多次、每次少量边（`edges` 指定点） |
| `nx_chamfer` 对已倒角/曲线边 | `Inappropriate edge for Chamfer. | Investigate the geometry.` | 工具会自动只用直线边重试并报告条数 |
| Parasolid 导出 | `Part has no valid export objects` | 用 STEP/IGES/STL |
| `nx_pdf` 的 SVG 路线 | `PrintSVGBuilder` 没有 `Filename`，`Commit()` 不产文件 | 只用 PDF |

## 9. NX 自带 CAE（CAD→FEM 关联）在 batch 下必崩

`fem.NewFemCreationOptions()` → `SetCadData(cadPart, "")` → `fem.FinalizeCreation(opts)` 抛
`NXException('Internal error: memory access violation')`；事后 `fem.Bodies` 变成 1 但下一步 `BaseFEModel`
变成 `None`，网格 builder 一律 `Internal error`。三种 finalize 变体（带 idealized 名 / `SetAutoGenIdeal(True)` / 只 SetCadData）全崩。

- 结论：NX 自带网格器拿不到几何，**不要走这条路**。
- 本插件的 `nx_fea_*` 改走 **`NXNASTRAN\bin\nastran.exe` 直连**：自己生成结构化六面体网格与 BDF，
  解析 `.f06`，再用 Pillow 出报告图。代价是**只支持悬臂梁 + SOL 101 + 六面体格**；任意几何需要交互式 NX CAE。

## 10. 没有图形界面可自动化

- `ugraf.exe <part>`、`ugraf.exe <sim>` 都只停在起始页（syslog `UG_APP_NOPART`）；
- `ugraf.exe -run_journal <script>` 不执行 journal；
- `run_journal.exe -nx <journal>` 能跑需要交互 API 的 journal，但窗口是黑屏，不渲染；
- 向 NX 注入输入不可靠：`SendKeys "%f"` 只能打开"文件"菜单，后续 `{DOWN}{ENTER}`、`^o` 无效；`mouse_event` 点击无反应（截图 MD5 前后一致）。

**结论：不要尝试操作 NX 界面**，一切通过工具完成。需要人工看图就让用户自己打开 `samples/` 里的文件。

## 11. Motion 未注册（按需求排除）

`tools.js` 里没有 `motion_*` 工具，模型看不到这部分能力。但 `nxworker.py` 仍保留实现（`motion_open`、
`motion_status`、`motion_solve`、`motion_frames`、`motion_report`）与 `python/motion_viz.py`。
要彻底移除：

1. 删 `python/motion_viz.py`；
2. 在 `nxworker.py` 里删 `motion_*` 的 handler 函数，并从 `handlers` 字典里去掉这 5 个键；
3. `nx_session action=restart`。

（保留它们不影响使用，`nx_status` 的 `commands` 列表里会看到这几个名字。）

## 12. 会话状态相关的坑

- **一个会话只有一个工作 part 上下文**：同路径 part 若仍被引用，`nx_new` 会报
  `… is open in this session and could not be closed`。解法：`overwrite:true`、换路径、或 `nx_session restart`。
- `nx_drawing` 的 `views` 必须是**对象**（`{front:true,…}`），传数组报 `TypeError: list indices must be integers`。
- 图纸建多了删不掉：`DraftingDrawingSheetCollection` 只有 `InsertSheet` 等，**没有删除方法**。
  所以一次只建一个图幅；要重来就重建 part（`nx_new overwrite:true` 或新路径）。
- CAE 报告图需要 Pillow：只有 DSH 自带 python 有（`…\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe`）。
  找不到时 `cae_run.py` 会跳过 PNG（try/except），求解结果照样返回。
- 图层：`LayerManager.GetStates()` 返回 `StateCollection`，**不能 `len()`、不能下标**，只能 `GetState(i)` 逐层查；
  状态值对象只能用 `str()` 比对（没有 `ValueOf()`）。`MoveDisplayableObjects(layer:int, objects:list)` 参数顺序如此，
  反了报 `First parameter is invalid. Expecting int type, found list.`。移动实体时 NX 会把它的从属显示对象一起带走，
  所以"对象数"看起来不是 1。
- 引用集：`part.CreateReferenceSet()` **无参**，返回对象后 `SetName()` / `AddObjectsToReferenceSet(list)`；
  删除只能按对象 `part.DeleteReferenceSet(refset)`（不接受名字）。`AskMembersInReferenceSet()` 的成员数含从属对象。

## 13. 没有干涉检查 API

`NXOpen` 里**不存在**干涉检查接口：`NXOpen.Assemblies` 只有 `ClearanceSetInterferenceStatus/Type(MemberType)` 枚举与
`ProductInterface`；`part.ComponentAssembly`（152 个成员）无任何 interference 方法；`ca.ClearanceSets` 只有
`CountClearanceSets/DeleteAllAnalysisData/FindObject`；`part.MeasureManager` 也没有（它有
`NewDistance/NewMassProperties/NewFaceProperties/NewSectionInertia/CreateMeasureMasterBuilder` 等）。

- 所以 `nx_assembly_clearance` 用**几何距离**代替：组件两两 `Measurement.GetMinimumDistance`，
  距离 < `tolerance` 判为干涉、`threshold` 只列更近的对。它能发现"穿透/贴合"，但**给不出干涉体积与穿透深度**
  （教程里那种表格要靠 NX 图形界面的干涉检查）。
- 同理，`part.MeasureManager` 的测量标注（`CreateDimensionAnnotation`）尚未封装成工具。


## 14. 外螺纹（螺柱/凸台）在本安装里建不出来

`ThreadBuilder` 的外螺纹分支一律失败：`MatchThreadSizeToCylinder=True` 报
`Invalid shaft size. Must be between major and minor diameters.`（ShaftDiameter 解析成 0），
手工给 shaft 直径后恒报 `Thread depth must be greater than zero.`，详细外螺纹直接
`Internal error: memory access violation`。根因是 `NX_Thread_Standard.xml` 里只有
`ThreadedHole` 行、没有 `ThreadedShaft`——精简安装缺外螺纹数据。内螺纹完全可用。

## 15. 投影视图没有隐藏线

批处理会话不生成隐藏边：`view.Style.HiddenLines.Hiddenline` 读回 True，但把
`RenderingStyle` 换成 `WireframeWithHiddenEdges`、把 HiddenLine 设 False 再 True、
`UpdateViews` / `UpdateSheetsAndViews` / `Regenerate` 全试过，导出的 PDF **逐字节相同**
（42151 与 42152 只差 1 字节），解码 PDF 内容流也找不到任何虚线操作符。要看内部结构只能用
`nx_section_view`（剖视走制图引擎，能算出剖面）。

## 16. 局部放大视图只有边界圈，内容空白

`CreateDetailViewBuilder` 能建、位置也精确（`Origin.Placement` 生效，`Scale` 读回 = 倍数 × 0.4172），
但视图内容是空的（只有边界圆和 "DETAIL x SCALE 2:1" 标签），`AskVisibleObjects()` 返回 1–3 个对象。
和隐藏线同源：batch 没有图形/消隐通道。工具保留，但要用它的内容得人工在 GUI 里更新视图。

## 17. 直纹面 / 扫掠 / 投影 / 相交 / 回转片体：提交即死

| builder | 报错 |
| --- | --- |
| `CreateRuledBuilder` | `The Tolerance Specification requires three numbers`（任何截面构造都一样） |
| `CreateSweptBuilder` | `Unable to approximate guide string.` |
| `CreateProjectCurveBuilder` | `Invalid faces or planes to project to.`（面、体、沿面法向都试过；`Tolerance` 还必须先设 ≥1e-5） |
| `CreateIntersectionCurveBuilder` | `No objects for intersection curve`（`FirstSet` 里明明有 body） |
| `CreateRevolveBuilder`（片体） | `Internal error: memory access violation` |

替代方案：直纹面用 `nx_surface kind=through_curves` 传 2 个截面（实测面积与 hypot 完全吻合），
回转体用 `nx_revolve`（实体）。

## 18. 草图尺寸建不出来

`sketch.CreateDimension(...)` 的所有重载都拒绝（`No overload matches these arguments` /
`Function takes 2 arguments`）。草图的几何与水平/垂直/重合约束可用，但尺寸标注不行；
参数化靠 `nx_expression`。

## 19. 明细表不是 NX 的关联零件表

NX 没有 tabular note / parts list 的创建 API（`part.Annotations` 只有 note、GDT、datum 一类，
`part.ParameterTables` 是零件族表）。`nx_bom_table` 画的是**图纸曲线 + 每格文字**，改完装配
必须重新跑一次；另外它不知道"零件名"业务含义，名称列在等于零件号时留空。

## 20. 视图比例的读回值带一个 0.4172 的基准

A1 图纸上 `view.Scale` 读回 `实际出图比例 × 0.4172`（该图纸自动适配得到的基准），
所以用 `CreateBaseViewBuilder` 设 `Scale.Numerator/Denominator` 时要写**想要的出图比例**
（0.5 → 实际 1:2）；用 0.5/0.4172 反而把图放大到 1:1.2。`DraftingView.SetScale()` 直接调用
会被拒绝（`View may not be scaled nor translated`）。另外 `SetDrawingReferencePoint` 只移动
该视图本身，**不带动投影视图**。

## 21. 装配体不能直接导 STL

`nx_export stl` 对装配体报 `the part has no solid body yet`。装配的整体网格走面板预览
（`/dsh-nx/preview` 会递归收集叶子组件），或导出某个组件。

## 22. 装配里"0 kg"的陷阱

大装配的组件是轻量加载的，`Prototype.Bodies` 为空 → 体积/质量读成 0。
`bom_rollup()` 现在先 `fully_loaded(component)` 再量；仍无质量（零件没赋材质）时按钢
7.85 g/cm³ 估算并在表里打 `*`。铣面夹具这次就因此把总重从 14.9218 修正到 17.7911 kg。

## 23. Nastran 需要显式内存参数

默认 open-core 申请 14 GB，桌面（NX batch 常驻）直接 `OPEN CORE Allocation Failed`，
连 f06 都不出。`cae_solid.py` 固定传 `mem=2000mb`（可用 `NXC_NASTRAN_MEM` 覆盖）；
带 mem 后 `nastran.exe` 返回码仍是 1，判断成功以 f06 是否生成、日志里有 `NSEXIT: EXIT(0)` 为准。
